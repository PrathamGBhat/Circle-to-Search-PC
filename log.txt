Q: python-dotenv
A: **`python-dotenv`** is a popular Python library that reads key-value pairs from a `.env` file and sets them as environment variables. 

It is widely used to store sensitive information (like API keys, database passwords, and configuration settings) separately from your source code, following the **12-Factor App** methodology.

---

### 1. Installation

You can install it using `pip`:

```bash
pip install python-dotenv
```

---

### 2. Basic Usage

#### Step A: Create a `.env` file
In the root directory of your project, create a file named `.env` (no prefix, just the extension) and add your variables:

```env
# .env file
API_KEY=your_secret_api_key_here
DATABASE_URL=postgresql://user:password@localhost:5432/mydb
DEBUG=True
PORT=8000
```

#### Step B: Load variables in Python
In your Python script, import `load_dotenv` and use `os.environ` to access the variables:

```python
import os
from dotenv import load_dotenv

# Load the environment variables from the .env file
load_dotenv()

# Access the variables
api_key = os.getenv("API_KEY")
db_url = os.getenv("DATABASE_URL")
port = os.getenv("PORT")

print(f"API Key: {api_key}")
print(f"Database URL: {db_url}")
print(f"Port: {port} (Type: {type(port)})") # Note: Environment variables are always strings!
```

---

### 3. Key Features & Advanced Usage

#### Feature A: Do Not Override Existing System Variables (Default)
By default, `load_dotenv()` **will not** overwrite existing system environment variables. If you want to force it to overwrite them, use `override=True`:

```python
load_dotenv(override=True)
```

#### Feature B: Custom `.env` File Path
If your `.env` file is in a different directory or has a different name (e.g., `.env.dev`), you can specify the path:

```python
from pathlib import Path
from dotenv import load_dotenv

env_path = Path('.') / '.env.dev'
load_dotenv(dotenv_path=env_path)
```

#### Feature C: Variable Expansion (Referencing other variables)
`python-dotenv` supports referencing other variables inside your `.env` file:

```env
DOMAIN=example.com
EMAIL_SUPPORT=support@${DOMAIN}
```
If you load this, `EMAIL_SUPPORT` will automatically resolve to `support@example.com`.

---

### 4. Best Practices (Crucial for Security)

1. **NEVER commit your `.env` file to GitHub/Git.**
   Add `.env` to your `.gitignore` file immediately.
   ```text
   # .gitignore
   .env
   ```

2. **Create a `.env.example` file.**
   Since you aren't committing `.env`, create a template file called `.env.example` containing the keys but placeholder values. Commit this to Git so other developers know what variables are required.
   ```env
   # .env.example
   API_KEY=your_api_key_here
   DATABASE_URL=your_database_url_here
   ```

3. **Convert Types:**
   Remember that `os.getenv()` always returns a **string**. If you need an integer or boolean, you must convert it manually:
   ```python
   DEBUG = os.getenv("DEBUG") == "True"
   PORT = int(os.getenv("PORT", 8000)) # 8000 is the default value
   ```
