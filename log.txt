Yes, FastAPI has a built-in router called `APIRouter`. It's specifically designed to help you split your endpoints across multiple files, which is essential for keeping medium-to-large projects organized.

### Basic Usage
```python
from fastapi import FastAPI, APIRouter

app = FastAPI()

# 1. Create a router
user_router = APIRouter()

@user_router.get("/users/")
def list_users():
    return [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]

@user_router.post("/users/")
def create_user(name: str):
    return {"id": 3, "name": name}

# 2. Include it in the main app
app.include_router(user_router, prefix="/api/v1", tags=["users"])
# Endpoints are now available at /api/v1/users/
```

### Key Features
- **Same decorators**: `@router.get`, `@router.post`, `@router.put`, `@router.delete`, etc.
- **`prefix`**: Adds a shared path segment to all routes in that router.
- **`tags`**: Automatically groups routes in the auto-generated Swagger/Redoc UI.
- **`dependencies`**: Apply global dependencies (like auth or validation) to all routes in the router.
- **Chaining & nesting**: You can include routers inside other routers if needed.

### When Do You Need It?
- **Small scripts/projects**: You can just use `@app.get()` directly on the `FastAPI` instance. Routers aren't strictly required.
- **Larger apps**: Routers are highly recommended. They keep code modular, improve testability, and make collaboration easier.

Yes, **FastAPI absolutely has a router**. It's called `APIRouter`, and it's the recommended way to organize routes as your app grows.

### Quick Example
```python
from fastapi import FastAPI, APIRouter

app = FastAPI()

# Create a router
user_router = APIRouter(prefix="/users", tags=["users"])

@user_router.get("/")
def get_users():
    return ["alice", "bob"]

@user_router.post("/")
def create_user(name: str):
    return {"user": name}

# Include the router in the main app
app.include_router(user_router)
```

### Direct `app` methods vs `APIRouter`
- `app.get()`, `app.post()`, etc. are **convenience methods** that attach routes directly to the app instance. They work perfectly fine for small scripts or single-file apps.
- `APIRouter` lets you:
  - Group related endpoints together
  - Apply a shared `prefix` and `tags` (useful for Swagger/OpenAPI UI)
  - Split routes across multiple files/modules
  - Reuse the same router in multiple apps (e.g., staging vs production)

Under the hood, both use FastAPI's same routing engine. The only difference is organization and scalability.

### Typical Project Structure
```
app/
├── main.py          # app = FastAPI() + app.include_router(...)
├── routers/
│   ├── __init__.py
│   ├── users.py     # router = APIRouter(prefix="/users")
│   └── items.py     # router = APIRouter(prefix="/items")
```
